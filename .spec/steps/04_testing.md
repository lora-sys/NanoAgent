# 测试计划

## 阶段 ID
stage_4

## 描述
测试和验证

## 成功标准
成功标准：
- [ ] 所有核心页面（首页、特性、架构、联系）加载无控制台错误，路由跳转正常
- [ ] 联系表单验证逻辑生效，非法输入（空值、错误邮箱格式）阻止提交并提示错误
- [ ] 响应式布局在移动端（<768px）、平板（768px-1024px）及桌面端显示无错位
- [ ] TypeScript 编译通过且无类型错误，ESLint 检查无报错
- [ ] 核心功能页面在 Lighthouse 性能测试中得分不低于 90 分

### Always (必须做)
- 必须覆盖所有需求文档中列出的功能点进行测试
- 必须记录测试过程中发现的所有缺陷及其复现步骤
- 必须验证蓝色主题在不同屏幕亮度下的可读性
- 必须检查所有图片资源是否加载完整且无破损
- 必须确保代码仓库中包含最新的部署说明文档

### Ask First (先询问)
- 是否需要集成自动化测试框架（如 Jest 或 Cypress）并交付测试脚本？
- 目标投资人是否有特定的浏览器或设备偏好需要优先兼容？
- 是否有可用的测试服务器或临时域名用于部署验证？

### Never (绝对禁止)
- 禁止使用真实个人敏感信息进行表单提交测试
- 禁止在存在 Critical 级别 Bug 未修复的情况下标记测试通过
- 禁止跳过移动端兼容性测试直接交付
