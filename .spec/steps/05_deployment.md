# 部署指南

## 阶段 ID
stage_5

## 描述
部署和交付

## 成功标准
成功标准：
- [ ] 网站成功部署至公共网络，可通过 HTTPS 链接访问且无 404 错误
- [ ] 在桌面端设备上，Lighthouse 性能与无障碍评分均不低于 90 分
- [ ] 联系表单在生产环境中完成提交测试，无控制台报错且触发成功反馈
- [ ] 部署文档清晰完整，第三方技术人员可依据文档在 30 分钟内完成重现部署

### Always (必须做)
- 必须提供 `.env.example` 文件，明确列出所有所需的环境变量及其用途
- 生产构建必须启用代码压缩、Tree Shaking 及静态资源优化
- 文档中必须包含 CI/CD 流程说明或手动部署的详细步骤及回滚方案
- 必须配置安全响应头（如 CSP, HSTS）以增强网站安全性

### Ask First (先询问)
- 您倾向于使用哪种托管服务平台（如 Vercel, Netlify, AWS S3 + CloudFront）？
- 联系表单的数据需要发送至哪个具体的后端 API 端点或第三方服务？
- 是否已经购买了自定义域名，是否需要协助配置 DNS 解析？

### Never (绝对禁止)
- 禁止在源代码或版本控制中硬编码任何 API 密钥、密码或敏感凭证
- 禁止部署包含 `console.log` 调试语句或未移除的开发模式警告的生产版本
- 禁止在不启用 HTTPS 加密的情况下将网站暴露于公网

交互提示：
为了定制最适合的部署方案，请告知您偏好的托管服务平台（例如 Vercel、Netlify 或 AWS），以及联系表单是否需要对接具体的后端 API 地址或使用第三方表单服务？
