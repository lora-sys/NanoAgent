# 接口设计

## 阶段 ID
stage_2

## 描述
设计和规划

## 成功标准
成功标准：
- [ ] 所有 API 接口（包括联系表单）必须定义完整的请求/响应 TypeScript 类型
- [ ] 所有 React 组件必须定义明确的 Props 接口文档
- [ ] 接口设计必须支持响应式断点配置的定义
- [ ] 表单验证规则必须在接口层有明确的类型约束
- [ ] 接口文档需通过技术负责人评审后方可进入开发阶段

### Always (必须做)
- 所有数据结构必须使用 TypeScript 接口或类型别名定义
- API 响应格式必须统一包含状态码、消息体和数据负载字段
- 组件接口设计必须遵循单一职责原则，避免过度耦合
- 必须定义全局主题配置接口以支持蓝色科技感主题
- 所有公共接口必须包含 JSDoc 注释说明用途和参数

### Ask First (先询问)
- 确认联系表单提交后是否需要对接真实邮件服务还是仅做模拟反馈
- 询问技术架构图是否需要交互式数据加载，以便定义异步接口
- 确认是否有现有的品牌色彩规范用于定义主题接口中的颜色值

### Never (绝对禁止)
- 禁止在接口定义中使用 `any` 类型规避类型检查
- 禁止将后端密钥或敏感逻辑暴露在前端接口定义中
- 禁止设计无法通过 TypeScript 严格模式编译的接口结构

交互提示：
需要确认联系表单的具体字段需求（除姓名、邮箱、消息外是否需要公司/职位？），以及技术架构图是否需要交互式点击展示详情，以便定义相应的数据接口结构。
