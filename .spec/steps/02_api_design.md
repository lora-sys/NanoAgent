## 描述
设计和规划

## 成功标准
成功标准：
- [ ] 完成至少 5 个核心数据接口的定义文档（如公司概况、财务预测、能源数据等）
- [ ] 所有接口响应格式统一为 JSON 且包含标准状态码字段
- [ ] 接口字段命名规范一致（如统一使用 camelCase 或 snake_case）
- [ ] 定义明确的错误处理机制和异常返回结构
- [ ] 接口设计需通过前端组件数据需求评审，确保无冗余或缺失

边界约束：
### Always (必须做)
- 必须使用标准的 HTTP 动词（GET, POST, PUT, DELETE）定义操作
- 必须为每个接口字段提供数据类型和必填项说明
- 必须考虑接口的版本控制策略（如 URL 中包含 v1）
- 必须定义分页参数规范用于列表数据接口
- 必须标注涉及敏感业务数据接口的鉴权要求

### Ask First (先询问)
- 询问前端页面需要展示的具体图表类型及数据频率（实时/静态）
- 询问是否有现有的后端服务或需要完全模拟数据接口
- 询问商业计划书中哪些数据属于公开展示，哪些需要权限控制

### Never (绝对禁止)
- 禁止在接口响应中直接暴露数据库主键或敏感内部逻辑
- 禁止设计返回 HTML 片段而非数据结构的接口
- 禁止忽略网络延迟和空数据状态的接口定义

交互提示：
为了完成接口设计，我需要了解：1. 前端页面具体需要展示哪些商业计划模块（如市场分析和财务数据是否需要动态交互）？2. 数据来源是现有 API、数据库还是需要我设计模拟数据结构？3. 目标用户是投资人还是公众，这会影响数据接口的安全级别设计。
