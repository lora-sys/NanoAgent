# 需求对齐

## 阶段 ID
stage_1

## 描述
明确需求和目标

## 成功标准
成功标准：
- [ ] 用户确认核心功能清单（首页、特性、架构、联系表单）无误
- [ ] 用户确认技术栈（React + TypeScript）与设计风格（现代科技蓝）符合预期
- [ ] 用户确认交付物包含完整源代码及部署说明文档
- [ ] 用户确认内容策略侧重面向投资人与合作伙伴的商业价值展示

### Always (必须做)
- 严格遵循 React + TypeScript 技术栈进行架构设计
- 确保所有页面实现完全响应式布局以适配多端展示
- 联系表单必须包含前端验证逻辑以确保数据有效性
- 交付物必须包含清晰的部署说明文档以便后续上线

### Ask First (先询问)
- 是否已有品牌资产（如 Logo、特定色值、字体）需提供？
- 目标部署平台是否有偏好（如 Vercel、Netlify 或自有服务器）？
- 产品特性与技术架构的具体文案内容是否由用户提供？

### Never (绝对禁止)
- 禁止在需求未确认前开始编写核心业务代码
- 禁止使用非约定的技术栈（如 Vue、纯 JavaScript 等）
- 禁止实现真实后端逻辑，仅使用 Mock 数据用于演示

交互提示：
请确认上述功能清单与技术约束是否符合您的预期？另外，关于品牌资产（Logo/色值）、部署平台偏好以及具体文案内容，您是否有现成的资料可以提供，还是需要我为您生成占位内容？
