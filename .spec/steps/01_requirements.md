# 需求对齐

## 阶段 ID
stage_1

## 描述
明确需求和目标

## 成功标准
成功标准：
- [ ] 用户明确确认了 GreenEnergy 的核心业务模式与目标市场
- [ ] 用户确认了商业计划书的重点章节结构与受众群体
- [ ] 用户确认了前端页面的核心功能、技术栈偏好及设计风格
- [ ] 双方就交付物的格式（如 PDF、代码仓库）与时间节点达成一致

边界约束：
### Always (必须做)
- 确认用户对于“绿色能源”的具体细分领域定义（如太阳能、风能、储能等）
- 明确商业计划书与前端页面的优先级和相互关联性
- 确保所有建议符合初创公司的资源现状与可行性
- 保持专业、清晰且具鼓励性的沟通语气
- 记录所有确认的需求点以备后续阶段查阅

### Ask First (先询问)
- 询问是否有现有的品牌视觉规范（Logo、主色调、字体）
- 询问前端页面是否需要对接实际后端接口或仅为静态展示
- 询问商业计划书是否有特定的字数、页数或模板限制

### Never (绝对禁止)
- 禁止在未确认需求前生成完整的商业计划书正文
- 禁止在未确认技术栈前编写具体的前端代码
- 禁止虚构具体的财务数据、法律承诺或未经证实的市场数据

交互提示：
为了精准对齐需求，请告诉我：1. GreenEnergy 的核心业务具体是什么（例如：太阳能安装、能源管理软件、碳交易平台）？2. 商业计划书的主要阅读对象是谁（投资人、银行、内部团队）？3. 前端页面是用于演示概念、获取潜在客户线索，还是作为产品原型？4. 您偏好的前端技术栈或设计风格是什么？
