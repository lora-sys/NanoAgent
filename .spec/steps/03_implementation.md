## 成功标准
成功标准：
- [ ] TypeScript 编译无错误且所有组件 Props 和 State 都有明确类型定义
- [ ] 联系表单具备前端验证逻辑，无效输入无法触发提交动作
- [ ] 所有指定页面（首页、特性、架构、联系）通过路由可访问且内容正确渲染
- [ ] 页面在不同屏幕宽度下（移动端/桌面端）布局自适应无错位

### Always (必须做)
- 使用 React 函数组件和 Hooks 编写所有业务逻辑
- 所有组件 Props 和 State 必须定义明确的 TypeScript 接口或类型
- 表单提交逻辑必须包含加载状态（loading）和错误处理机制
- 代码结构必须按功能模块划分文件夹（如 components, pages, hooks, utils）
- 必须实现响应式断点逻辑以适配移动端显示

### Ask First (先询问)
- 联系表单提交后是需要模拟成功提示还是对接真实后端接口？
- 对于“现代科技感”是否有指定的动画库偏好（如 Framer Motion 或 GSAP）？
- 技术架构图是需要静态图片展示还是可交互的组件？

### Never (绝对禁止)
- 禁止在代码中使用 `any` 类型绕过 TypeScript 检查
- 禁止将 API 密钥或敏感信息硬编码在客户端代码中
- 禁止使用阻塞主线程的同步操作处理表单提交
